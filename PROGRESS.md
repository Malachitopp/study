## Current state (2026-08-09)

**Everything below this heading predates 2026-08; read this section first.** Since the 2026-07-30 entry the app has gained a hooks layer, a full delete/archive policy, swipe gestures, form-sheet routes, the TaskRow money story, the Money screen, and four new server-side guards. The commits are on GitHub (`https://github.com/Malachitopp/study.git`, remote `origin`, branch renamed `master` → `main`).

**Hooks layer (frontend).** Data fetching moved out of screens into `mobile/hooks/`: `use-commitments.ts` (`{commitments, loadCommitments}` — flat `GET /commitments/` with its own `useFocusEffect`), `use-tasks.ts` (flat `GET /tasks/`), `use-load-tasks.ts` (scoped `GET /modules/{id}/tasks/`, takes a `moduleId`), `use-create-tasks.ts` (owns the create-task *form state* plus `handleCreateTask`, takes `(moduleId, onCreated)`). Two lessons paid for in blood: (1) **the two-clock 401 race** — the module screen guarded its trigger effect on *its own* `useAuthToken` token while the hook fetched with the *hook's* token instance (still `null`), sending `Bearer null` → 401 → logout on every visit. Law: a guard must read the same state instance as the code it guards; the fix was moving the trigger inside the hook. (2) **`use-tasks.ts` was deleted while uncommitted and was unrecoverable** — git is the only undo, so commit when a thing works. Naming ambiguity (`use-tasks` vs `use-load-tasks`) caused the deletion; the rename to `use-module-tasks` is still pending.

**Cooling-off cancel (backend, done + tested).** `commitments.created_at` added (`DateTime(timezone=True)`, `server_default=text('now()')`, migration `a967164396e5`; the backfill stamped all 28 existing rows identically because Postgres `now()` is transaction time). `settings.cool_off = 5` (minutes) in `config.py`. `POST /commitments/{id}/cancel` → 404 not yours, 409 if not `active`, 400 if older than the window, else `status = cancelled`. No ledger row — cancelling moves no money. Verified 7/7 by a scratchpad script (fresh → cancelled, double-cancel → 409, completed → 409, past-window → 400, unknown → 404, refused row still active). The past-window case is untestable through the API, so the test backdates `created_at` with `db.execute(text("UPDATE ... - interval '10 minutes'"))` — the project's first deliberate raw SQL.

**Delete + archive policy (backend, done + tested).** `DELETE /modules/{id}` and `DELETE /modules/{module_id}/tasks/{task_id}`. The rule that emerged: **commitments are the boundary.** A module/task with *active* commitments → 409. With *any* commitment history → soft-archive (`archived` Boolean column on both `Module` and `Task`, `server_default=text('false')`; migrations `d78301ef6065` and `a55d45bdd507`). Virgin → hard delete (children first — FK is RESTRICT, not cascade). `list_modules`, `list_tasks` *and* the flat `get_tasks` all filter `archived == False`, so the client needed **zero changes**: absence from the list is the UI. `archived` is deliberately *not* in `ModuleOut` or the client types — the client never sees an archived row, so the field would always be `false` and carry no information. Why soft-delete at all: hard-deleting a storied module would require deleting its commitments, which would require deleting `transactions` rows — and the ledger is append-only. Verified 11/11 by scratchpad script.

**Two more create-time guards (backend, done + tested 5/5).** `create_commitment` now refuses (400) a deadline less than `required_seconds` away — an unwinnable bet, charged automatically within a minute of creation — and refuses (409) a *second active* commitment on the same task (two live stakes, one check-in, the loser charges you for work you did). The status filter matters: a task whose commitments are all completed/cancelled must still be re-stakeable, and that regression is in the test.

**Swipe-to-delete + confirm (frontend).** `GestureHandlerRootView` wraps the app in the root `_layout` (`flex: 1`, or the whole app collapses). `ReanimatedSwipeable` (imported from `react-native-gesture-handler/ReanimatedSwipeable` — the package-root `Swipeable` is deprecated) wraps `ModuleCard` on Plan and `TaskRow` on the module screen; `renderRightActions` returns a red `Pressable` whose `onPress` opens `Alert.alert(title, message, [{style:'cancel'}, {style:'destructive', onPress}])`. Refusals surface via `Alert` with the server's `detail`. **Trap worth remembering:** a 204 has an empty body, so `.json()` *throws* — parse only inside the `!response.ok` branch.

**Form sheets (frontend).** The module screen's two inline forms are gone. `app/new-task.tsx` and `app/new-commitments.tsx` are routes registered in `_layout` with `presentation: 'formSheet'`, `sheetAllowedDetents: 'fitToContents'`, `sheetGrabberVisible`, `sheetCornerRadius: 24` — iOS draws the sheet, no Reanimated needed. Identity travels in the **query string** (`/new-task?moduleId=7`, `/new-commitments?taskId=3`) and is read with the same `useLocalSearchParams`; query params need no `[brackets]` in the filename, unlike path params. `useCreateTasks`'s `onCreated` callback is now `() => router.back()` from the sheet (it was `loadtasks` from the screen) — same hook, different ending, which is the point of the callback prop. The stake sheet fetches its task (`GET /tasks/` + `.find`), seeds the deadline picker from `task.due_at` (**default**, not value — a sheet due Friday can carry a commitment for tonight), offers preset stake and minute chips, shows a summary card with a compact inline picker, and guards positive stake/minutes plus the winnable-deadline rule client-side.

**TaskRow (frontend).** One badge per task derived from its commitment history — STAKED / LOST / KEPT / NO STAKE, precedence in that order so live money always wins — via `filter` + `reduce` per status inside the component (screens pass the raw `commitments` array; cards digest). The "Put money on it" CTA renders on `stakedPence === 0 && due_at > now`, *not* on the badge being NO STAKE: badge answers "what's the money story", CTA answers "can I stake now", and conflating them made completed tasks permanently un-re-stakeable.

**Money screen (frontend).** `Money` headline, a "currently at risk" hero card (44px total, one bar segment per live commitment via `active.map`), three `Tile`s (kept / lost / kept-rate, with the 0/0 → NaN case guarded), then the ledger as a `FlatList` of `TransactionRow`s. `TransactionOut` gained `task_title` via a **`@property` on the `Transaction` model** (`self.commitment.task.title`) — same trick as `CommitmentOut.task_title`, no migration, and an N+1 per row. Every ledger row is a charge (the worker is the only writer, one hardcoded reason), so amounts are unconditionally `danger` red with a `-` prefix; the long stored reason string is a log message, so the row derives a short label from it.

**AppButton variants.** `selected` (now accent-tinted + accent border, green *text*; it used to be a solid green fill — green means success/kept, not "currently chosen"), `cancel` (card fill, danger border — quiet destructive), `ghost` (dashed border, muted text — "add" affordances), `stake` (chip: `flex: 1`, card fill, border — preset rows). `components/tile.tsx` holds the stat tile with a `tone` and `percentage` prop.

- `routers/transactions.py` — `my_transactions`: `GET /transactions/`, the flat user-scoped ledger read (four-hop join `Transaction → Commitment → Task → Module`, filtered on `Module.user_id`; `TransactionOut` schema in `schemas/transaction.py`). Read-only — the ledger stays append-only, written solely by the worker.

Uses its own `SessionLocal()` directly (not `Depends(get_db)`, since it's not triggered by an HTTP request). Has its own `has_checkin → completed` branch, but that's now just a backstop — the endpoint above completes commitments in real time, so the worker only ever meets genuinely abandoned ones.

## Environment gotchas (things that already bit us once)

- **Always run the server with `uvicorn app.main:app --reload` from inside `backend/`.** Never the VS Code ▷ Run button or `python app/main.py` directly on any file inside `app/` — both break imports, since `app` is only importable when `backend/` is the working directory.
- **`bcrypt` is pinned to `4.0.1`** in `requirements.txt`. Newer `bcrypt` releases break `passlib` (unmaintained since 2020) — don't let this get unpinned by an unrelated `pip install --upgrade`.
- **`access_token_expire_minutes` is `15`.** Swagger UI's "Authorize" token goes stale quickly during a long debugging session — a `401 "Invalid or expired"` often just means re-click Authorize and log in again, not a real bug.
- **All four model files must stay imported together** (via `models/__init__.py` + `from app import models` in `main.py`). SQLAlchemy resolves `relationship("Task")`-style string references by scanning whatever classes have actually been imported somewhere in the process — skip importing one model and every mapper fails to configure the moment any query runs.
- **`ForeignKey("tablename.column")` uses the actual DB table name** (`tasks`, plural), **`relationship("ClassName")` uses the Python class name** (`Task`, singular). Easy to mix up; SQLAlchemy's error messages for this are a bit cryptic (`NoReferencedTableError`).
- **Both sides of a `back_populates` pair must name each other exactly** — `A.b = relationship("B", back_populates="a")` requires `B` to have an attribute literally named `a`. Got this wrong twice (`Module`/`Task`, then `Commitment`/`Checkin`/`Transaction`) — a mismatch doesn't fail until the first real query anywhere in the app, and the error (`Mapper 'X' has no property 'y'`) can look unrelated to the actual broken pair.
- **`Base.metadata.create_all()` only creates missing tables — it never alters an existing one.** Changing a column's type (or any other property) on a model that already has a live table requires either dropping and recreating that table (fine for disposable test data) or a real Alembic migration (needed once real data exists). Hit this directly with `Transaction.stripe_payment_id`.
- **`.env` holds the real Neon connection string and secret key** — confirmed never committed (`.gitignore` + `git check-ignore` both checked). Never paste its contents into a chat session.
- **Expo Go only supports one SDK version at a time** — whatever it currently ships with, not a range. `create-expo-app` always grabs the newest SDK by default, which can be ahead of what Expo Go on the App Store actually supports yet. If you hit "Project is incompatible with this version of Expo Go," pin the project to match: `npx create-expo-app@latest mobile --template default@sdk-54` (adjust the SDK number to whatever Expo Go currently reports).
- **A phone testing over Expo Go is a separate physical device from this PC** — `http://localhost:8000` or `127.0.0.1:8000` in fetch code means "this device," i.e. the phone itself, not the laptop. Use the PC's actual LAN IP (`ipconfig` → IPv4 address) instead, and run uvicorn with `--host 0.0.0.0` (the default `127.0.0.1` only accepts connections from the same machine, not from other devices on the network). The IP currently hardcoded in `API_URL` is `192.168.0.100`; if fetches start timing out, check this first.
- **`npx expo start` must be run from inside `mobile/`, not the repo root** — same class of trap as uvicorn needing `backend/`. The root has no `package.json`; both projects live one level down.
- **`mobile/AGENTS.md` says to read the v54 docs (`https://docs.expo.dev/versions/v54.0.0/`) before writing any Expo-specific code.** This bit us as a *non*-issue for the focus timer (plain React — `useState`/`useEffect`/`setInterval`, nothing versioned) but is real for anything touching an Expo/RN native component: the datetime picker this session, and camera/secure-store/navigation next. The date picker in particular is *not* a `keyboardType` — it's a separate component (`@react-native-community/datetimepicker`) whose `value` is a `Date` object, rendered inline on iOS but shown imperatively (`DateTimePickerAndroid.open`) on Android.
